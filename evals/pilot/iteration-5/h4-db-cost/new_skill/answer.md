# 数据库降本方案

## 结论

账单涨 40%、数据只涨 15%，说明钱主要不是花在"存数据"上，而是花在"用数据"（查询、扫描、副本、备份）和"为峰值买单"（过配、离散规格跳档）上。建议先花 1–2 周做账单归因，再按"先降需求、再降配置、最后锁价格"的顺序推进：两个季度降 25–35% 是现实目标，其中 8–12 个百分点可以在 30 天内、不改架构拿到。按 40% 复利，两年账单就翻倍，只做快赢撑不住，必须同时动结构和治理。

## 一、先证明 40% 从哪来，不要先优化

账单 = Σ(用量 × 单价)。数据量只是"存储"这一项的用量，存储最多贡献 15% × 存储占比：若存储占账单 30%，只解释 4.5 个百分点，剩下 35.5 个点来自非存储项——相当于那部分涨了约 50%。所以数据增长解释不了这个缺口。

归因切四刀：成本项（计算/存储/IOPS/备份/网络/许可）、环境（生产/非生产）、工作负载或租户、单位成本（元/GB·月、元/万次查询、元/租户）。同时看形态，两类走的路完全不同：

- **阶跃**：某个月突然跳涨 → 找那次变更（新租户、加副本、换规格、迁移、调价、支持等级）
- **斜率**：月月涨 → 找用量驱动（QPS、扫描行数、实例小时、保留天数）

再按增长集中项对照定位：

| 增长集中在 | 常见机制 | 先做什么 |
|---|---|---|
| 计算 | 查询变多/变慢、副本增加、规格跳档 | 慢查询与索引，再右规格 |
| IOPS | 热表超过内存，缓存命中率断崖 | 索引、分区、读缓存 |
| 存储 | 无归档、表膨胀、多副本 | 分层 + 归档 + 清理 |
| 备份/快照 | 保留期"永久"、孤儿快照 | 改保留策略，见效最快 |
| 网络 | 跨区/跨云复制、数据导出 | 改拓扑、就近读 |
| 许可 | 按核/按版计费、Edition 过高 | 降版、换引擎、谈约 |

还有一个容易漏的机制：规格是离散的。数据涨 15% 可能刚好让热表超过内存或跨过一档实例/存储，价格台阶式跳 40%——这时要做的是把工作集压回内存和低档区间（归档、分区、瘦表、拆冷热），而不是直接升档。

## 二、按顺序打，顺序错了会白花钱

**先降需求 → 再降配置 → 最后锁价格。** 反过来先买三年承诺，等于把低效基线锁死三年。

**第 1 档：无风险快赢（0–4 周，8–12%）**

- 非生产库按需启停、缩规格、禁止全量克隆生产数据（这类往往占总账单两三成）
- 清理孤儿快照、过期备份、临时表与日志；备份保留改 7/30/90 天分层
- 闲置只读副本、双活灾备降为温备
- 按 p95 而非峰值右规格，开自动伸缩
- 90 天未访问的数据转低频/归档层
- 用满已有承诺折扣；没测准前不要新签长约

**第 2 档：工程治理（1–2 季度，再降 10–20%）**

- 慢查询与索引：去掉全表扫描和 N+1。IOPS 和 CPU 降下来才敢降规格——顺序不能反
- 分区 + 归档：热/温/冷分离，历史数据进对象存储或列存
- OLTP 与报表分离：CDC 同步到分析库，别让大查询压生产库
- 合并碎片实例、连接池、读缓存、批处理异步化
- 查膨胀：vacuum/optimize、索引膨胀、WAL、临时空间，行数不变也能让物理体积翻倍

**第 3 档：结构性（半年以上，20–40%，风险高）**

- 商业库换开源（SQL Server/Oracle → PostgreSQL/MySQL），按核许可能降一大块
- 多租户分片、按租户配额与计量，把成本压到产生方
- 自建 vs 托管、换区域/换云重算 TCO
- 只对确认稳定的那部分签长约

## 三、怎么验收，别降出事故

- 主指标看**单位成本**（元/万次事务、元/GB·月、元/租户），不能只看总额——总额降了但单位成本没降，可能只是业务缩了
- 护栏：p95 延迟、错误率、复制延迟；备份每季度真做一次恢复演练
- 每月做一次"价 × 量 × 结构 × 效率"差异分析，设预算与异常告警
- 治理：所有库打标签（负责人/环境/成本中心），新库上线必须带容量与留存期估算

一个能提前止损的判据：**如果计算项用量（实例小时 × 规格）基本没涨、账单却涨了，问题在单价或结构，工程优化无效，应先去谈商务或改架构；反之若用量涨得比数据快，先做查询与索引治理。**

## 四、需要你确认的 5 件事

1. 什么引擎、自建还是托管、是否按核/按版计费
2. 账单中计算/存储/IO/备份/网络/许可各占多少，哪项涨得最快
3. 近 12 个月是阶跃还是斜率；若是阶跃，哪个月、当时改了什么
4. 非生产环境与只读副本各占多少
5. 现有承诺折扣覆盖率与到期时间；SLO 是什么

有第 2、3 项就能把方案收窄成一条主路径：计算涨最快 → 先索引与慢查询，再右规格；备份/快照涨最快 → 一周内改保留策略即可见效；单价涨 → 直接进商务谈判。
