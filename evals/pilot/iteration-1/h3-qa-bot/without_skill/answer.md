# 结论

能做，但不能做成"自动回答客户"的机器人。2 个人月内唯一能安全交付的形态是：客服输入问题 → 系统定位到文档里的具体条款 → 给出原文摘录、条款号和页码 → 客服确认后自己回复。让机器人直接对客户说话，在 2 人月内做不到合规可控；第二期可以加"生成回复草稿"，但仍然由人点发送。

判断依据：

- 200 页（约 10 万字）对检索式问答属于小语料，技术上不难。难的不是模型，是"答错零容忍"这个约束。
- 没有标注数据不致命，替代品是「客服真实问题清单 + 合规/法务逐条确认」。这部分人力必须由业务方出，不能算进 2 人月。
- 真正的瓶颈是**谁对"这条回答对不对"签字**。没有人能签字，做出来也上不了线。

# 四条设计原则

1. **答案只能来自文档，且必须带条款号和页码。** 数字、期限、比例、责任主体一律原文引用，不允许模型改写或概括。
2. **允许拒答，拒答是正常结果。** 检索置信度不足、问题跨条款、涉及免责/赔付/法律责任，直接转人工，不做"猜一个"。
3. **先做检索，后做生成。** 第一期只给人看原文位置，风险接近零、价值立刻可用；生成能力等评测集建好再上。
4. **不做微调。** 无标注数据、文档还会改版，微调没有收益，还会把幻觉固化进模型。RAG + 拒答阈值才是对的杠杆。

# 2 人月怎么排

## 第一期（约 3 周，1 人）：条款检索工具

- 文档结构化：按章/节/条切分，保留层级和条款号，不要按固定字数硬切；表格、附录单独处理。
- 混合检索：BM25 + 向量检索，取并集后重排。中文合规文档里条款号、专有名词、金额期限这类词，关键词检索经常比向量更准，两者都不能少。
- 输出形态：问题 → 前 5 条候选条款（命中句高亮 + 页码 + 条款号），客服自己读原文作答。
- 先给 3–5 个客服试用，把他们真实会问的问题记下来——这就是第二期评测集的原料。

## 第二期（约 5 周，1–2 人）：评测集 + 引用式回答

- **评测集 100–150 条**：每条标注「标准答案 + 必须引用的条款」。候选问题可以用模型生成，但必须由合规/业务负责人逐条确认。这是本项目关键路径，要提前排期，不能等系统做完再找人。
- 回答生成只允许「抽取 + 拼接 + 引用」：prompt 里强制"检索内容不足以回答时输出无法回答"；生成后再校验一次，回答里每个事实性陈述若在引用段落中找不到依据，就降级为只展示原文。
- 拒答阈值用评测集调，原则是宁可多转人工。
- 接入现有客服工作台（侧边栏或快捷键唤起），不做独立聊天窗口。
- **影子运行 1–2 周**：机器答案只给客服看、不直接对客户，记录采纳率和修改率，再决定是否放开。

# 合规闸门（不能省）

- **单一信源**：只检索这份文档，关闭联网，禁止模型拿自身知识兜底。
- **强制引用**：没有条款号 + 页码的回答不显示。
- **高风险白名单**：赔付、免责、时效、法律责任、监管报送类问题，只给原文，不给结论。
- **版本绑定**：文档改版后旧答案失效，回答上标注适用版本。
- **全程留痕**：保存问题、召回段落、模型输出、客服最终回复，供审计和事后追责。
- **红队测试**：30–50 条诱导性问题（"是不是可以不给退款""有没有例外"），验证它不会顺着问法编答案。

# 验收标准（建议直接写进项目书）

| 指标 | 目标 |
|---|---|
| 检索命中 | 95% 以上问题的正确条款出现在前 5 条 |
| 引用正确率 | 引用确实支持该回答，≥ 98% |
| 危险错误 | 无引用却给出确定性结论 = 0（设计上应不可能出现） |
| 覆盖率 | 60%–70% 可接受，其余转人工 |

覆盖率低不是失败，是必要的安全余量。

# 需要公司先确认三件事

1. **谁对答案负责**（合规或法务），能投入多少小时做评测集确认，能不能签字。
2. **客服真实高频问题清单**，哪怕只有 30 条。没有它，评测集只能凭空造，验收就是自说自话。
3. **这份文档是否已定稿、有没有内部矛盾条款。** 200 页合规文档大概率存在表述冲突，机器人一定会把它暴露出来——这是好事，但需要有 owner 裁决。

这三条给不了，2 个人月做出来的东西只能演示、不能上线。那种情况下更划算的做法是：先花两周只做「条款检索 + 全文搜索优化」当内部工具用，等业务方准备好评测集和签字人，再谈问答。
