# 结论

能做。但 2 个人月能交付的不是"问答机器人"，是"客服的政策查询副驾驶"。

够用的形态是：客服打出问题 → 系统给出条款号、页码和原文 → 客服确认后自己回复。覆盖 30–50 个高频意图，证据不足就转人工，永远由人点发送。全自动对客的版本不该在这个资源下上线——不是模型不够好，是没有人能对"这条答错了"签字。

项目本质可以压成一句：**在给定的错误预算下尽量多答；难的不是检索，是"什么算对"没有标准、而错的代价不对称。**

这其实是经典的"选择性预测"问题——给定一个错误率上限，能答多少答多少，答不了就拒答。但经典方法假设模型的置信度是准的，而大模型会自信地答错，所以这里要换成可验证的证据条件，下面会讲。

# 为什么是这个结论

把"做个问答机器人"拆开，实际要同时满足两件事：客服更快拿到能引用的正确答案，公司不因此产生合规事故。这两件事的瓶颈不一样。

- **文档不是瓶颈。** 200 页大约 8–10 万字，整本放进模型上下文都放得下，检索和生成都是成熟工程，两周能出可用版本。
- **稀缺的是"可判定的标准答案"。** 没有标注数据，意味着现在没法回答"它答对了百分之多少"，也就没法证明风险可控。所以第一笔投入不该是写代码，是造那把尺子。
- **错误成本长尾且不对称。** 大多错答无害；但免责、赔付、时效、监管报送口径这几类错一次就是事故。用一个统一的"准确率 95%"去管，必然管错。

所以顺序要反过来：先定哪些题绝对不能错，再定哪些题可以不答，最后才谈模型和检索。

# 把风险闸门放在"人对客发送"，不放在模型准确率

这是整套方案里最省力也最有效的一条。只要客户收到的每句话都经过客服确认，模型出错的上限就是"客服看到一条错建议并忽略它"，而不是"客户收到一条错政策"。与其把准确率从 92% 磨到 97%，不如把这道人工闸门做进工作流——前者要几个月且没有尽头，后者是一周的集成工作。

在它之上再加三道结构化闸门，且都不依赖模型自评置信度：

1. **分级。** A 类（免责、赔付、时效、监管口径、法律责任）只展示原文，不给结论；B 类可给结论但必须带条款号；C 类文档没写，直接回"文档无依据"。
2. **证据条件。** 命中唯一且明确的条款、命中条款之间不冲突、生成的每句话都能在引用段里找到依据。任一不满足就转人工。这是可审计的规则，不是玄学调阈值。
3. **单一信源。** 只检索这份文档，关联网，禁止模型用自身知识兜底；回答绑定文档版本，改版即失效。

# 2 个人月怎么排（约 40 人天，8 周滚动）

先说成本结构：约 1/3 工程管线，1/3 评测与金标，1/3 集成与影子运行。合规同事裁决金标的时间（约 30 小时）不计入这 40 人天，但它在关键路径上，第一周就要排期，否则第 6 周必卡。

**第 1 周｜定范围。** 从工单和客服群捞 200 条真实问题，归并成 30–50 个意图，逐条判"文档可答 / 需人工 / 文档没写"，同时打 A/B/C 分级。这份清单就是项目范围，也是所有验收的边界。

**第 2–3 周｜检索与引用。** 按"条"切分并保留条款号层级——不要按字数硬切，条款号本身就是最强的检索特征。BM25 加向量混合召回再重排。这里有个更可靠也更省力的做法：前 50 个意图手工建"问题→条款"映射表。50 条的量两天能建完，比向量检索更准、更容易审计，而且它天然就是最早的评测基线。

**第 3–5 周｜造尺子（与上一步并行）。** 150–200 条金标：真实问题、标准答案、必须引用的条款，由合规逐条裁决。这是 2 人月里最值钱的固定资产——它同时是验收依据、回归测试集，也是将来任何自动化（包括真要微调时）的数据来源。

**第 5–7 周｜评测加影子运行。** 用金标卡门禁；同时接真实工单跑两周，答案只给客服看、不直接对客，记录采纳率、改写率和错误类型。这一步顺手解决"没有标注数据"：客服每改一次就是一条免费标注，前提是日志按数据集的字段来设计。

**第 7–8 周｜上线与交接。** 嵌进现有客服工作台（侧边栏或快捷键），不做独立聊天窗口；全程留痕（问题、召回段落、模型输出、客服最终回复）；交付文档、周复盘机制和改版失效流程。

# 验收标准（建议直接写进项目书）

| 指标 | 目标 |
|---|---|
| 引用正确率（引用条款确实支持该回答） | ≥ 98% |
| A 类问题出现无依据结论 | 0（设计上应不可能） |
| 已答问题正确率 | ≥ 95% |
| 转人工率 | 30–50%（低不是失败，是安全余量） |
| 影子期客服改写率 | ≤ 10% |
| 红队诱导问题（30–50 条） | 零顺从 |

比数字更重要的是最后一条：合规或法务对覆盖范围内每个意图签字。签得到字才算"能上线"，签不到就还是个演示。

# 明确不做

- **不微调模型。** 没有标注数据、文档还会改版，微调没有收益，还会把幻觉固化进权重。
- **不做全自动对客。** 第二期可以加"生成回复草稿"，但仍然由人发送。
- **不承诺覆盖 200 页。** 40–60% 的覆盖率是这个资源下的合理结果，剩下的本来就该人工处理。
- **不接账户系统做多轮个性化问答**（"我的保单""我的订单"），那是另一个项目，需要另一份预算。

# 需要你先确认三件事

1. **谁签字、能给多少小时。** 合规或法务出约 30 小时裁决金标集，是硬前提。
2. **能不能拿到 200–500 条真实客服问题。** 拿不到，金标集只能凭空造，验收就是自说自话。
3. **文档是否定稿、有无互相矛盾的条款、有没有 owner 能拍板。** 200 页合规文档大概率存在表述冲突，机器人一定会把它翻出来——这是好事，但得有人裁决。

这三条给不了，2 人月就只做到第 2–3 周那个形态：一个条款检索工具。它依然值得做——检索层是后面所有形态的地基，而且当下就能省客服翻条款的时间。
