**平均 O(1)，最坏 O(n)。**

原因：两者底层都是**哈希表**。查找时先用 `hash()` 把键映射到桶，找到后比较是否相等；表随元素增长扩容，装载因子保持在 2/3 以下，所以平均只需常数次探测。`set` 就是只存键、不存值的 `dict`，机制相同。

几点补充：

- 平均 O(1) 的前提是哈希值分布均匀。若自定义 `__hash__`/`__eq__` 写得不好（大量键落进同一桶），会退化。
- 最坏 O(n) 出现在所有键碰撞、退化为线性扫描时；Python 对 `str`/`bytes` 使用随机化哈希（`PYTHONHASHSEED`）让这种构造变难，但不改变理论上界。
- 严格说，O(1) 不包括算哈希本身的成本：哈希一个长度为 L 的字符串是 O(L)。
- Python 3.6+ 的 `dict` 保持插入顺序，但那是额外维护的紧凑数组，查找仍走哈希表。
