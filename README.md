# Tashan

Tashan 是一套可复用的思考指令（Agent Skill）。当问题复杂、目标不清，或常规方法反复失败时，它把分析过程固定为可执行的步骤：先澄清影响决策的事实，再从第一性原理推导因果，借用机制相同的成熟方法，最后用证据检验结论并给出可验证的答案。

## 它解决什么问题

一次性回答擅长处理直截了当的问题，但在以下情况容易失效：约束没弄清就开始给方案、沿用熟悉做法却反复碰壁、把假设当成事实、给出结论却没有验证路径。

Tashan 针对的是这些失效模式。它不提供领域知识，只约束思考顺序。

## 适用场景

- 问题复杂，多个因素相互制约
- 目标或约束不明确，方案取决于某个关键取舍
- 原因未知，需要从现象反推因果
- 常规做法反复失败，需要跳出既有路径
- 明确要求深度分析或第一性原理思考

简单直接的问题不需要它。Tashan 的第一步就是让投入与问题匹配，而不是对所有问题都展开长分析。

## 工作方式

1. **匹配投入**：能一两句定的事，就一两句答完并停，不展示过程；复杂问题才使用后续步骤。
2. **澄清**：区分期望结果与当前方案，先查已有证据，只问会改变决策的未决事实或取舍。
3. **第一性原理**：区分事实与假设，找出结果的真正成因，必要时重排步骤或拆开耦合环节；用户没给的数量是未知而非已知——要么标成假设并说明若不成立则换哪条路，要么删掉；把问题压缩成一句话——要决定什么、什么让它难。
4. **类比与重组**：把这句话还原为某个经典问题的变体，说明映射成立的因果机制与前提；借其成熟方法，再放下类比，用第一性原理按当前约束重新组合。
5. **验证**：用证据或反例检验结论；把无法验证的前提写成条件，说明什么情况下方案不可行；错误代价高的决定，额外给一个能推翻结论的测试和一个提前停手的观察点。
6. **清晰作答**：先给结论，再给关键原因、行动建议和验证方式。

## 安装

把整个 `tashan/` 目录放入所用 Agent 的技能目录。以 CodeArts Agent 的项目级技能目录为例：

```
<project>/.codeartsdoer/skills/tashan/
```

其他 Agent 的目录约定不同，核心要求只有一条：`SKILL.md` 所在目录名为 `tashan`，且 frontmatter 中的 `name` 与目录名一致。

## 调用

`SKILL.md` 的 `description` 已声明适用场景，Agent 会在条件匹配时自动加载。也可以显式点名：

> 用 tashan 分析这个问题：……

## 示例

输入：

> 线上接口白天正常，高峰期响应从 200ms 涨到 4s，日志里没有明显报错。请定位原因。

使用 Tashan 后，典型输出会先给出结论和判断依据，再列出需要业务确认的取舍，最后给出可执行的改动与验证方式；而不是直接猜测某个中间件出了问题。

## 状态

这是一个精简版（39 行），已通过 Agent Skills 格式校验。

2026-11-21 跑过一次小样本 pilot（8 题 × 2 臂、两个顺序对调的盲裁判，过程与原始数据见 [evals/pilot/iteration-1/benchmark.md](evals/pilot/iteration-1/benchmark.md)）：有 skill 的答案在 13 个有效判定中赢 11 个，五维总分 14.38 vs 13.69（满分 15），输出长度 1.05×。样本小、裁判同族、没有「等长通用提示」对照组，所以这只是方向信号，不足以宣称通用提升；简单题上它仍可能过度展开。

随后按这两个失败模式打了三处补丁（答完即停、未给的数量是未知、高价决定要有一条能证伪的测试），复测 3 题 × 2 臂：6 个判定全部判给新版本，13.33 vs 11.50，且不再出现虚构「吞吐没掉」或 simple 题长篇。过程见 [evals/pilot/iteration-2/RESULT.md](evals/pilot/iteration-2/RESULT.md)；这仍不是通用结论。
