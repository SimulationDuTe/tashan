# Tashan

Tashan 是一套可复用的思考指令（Agent Skill）。当问题复杂、目标不清，或常规方法反复失败时，它把分析过程固定为可执行的步骤：先澄清影响决策的事实，再从第一性原理推导因果，借用机制相同的成熟方法，最后用证据检验结论并给出可验证的答案。

## 它解决什么问题

一次性回答擅长处理直截了当的问题，但在以下情况容易失效：约束没弄清就开始给方案、沿用熟悉做法却反复碰壁、把假设当成事实、给出结论却没有验证路径。

Tashan 针对的是这些失效模式。它不提供领域知识，只约束思考顺序。

## 适用场景

- 问题复杂，多个因素相互制约
- 目标或约束不明确，方案取决于某个关键取舍
- 原因未知，需要从现象反推因果
- 常规做法反复失败，需要跳出既有路径
- 明确要求深度分析或第一性原理思考

简单直接的问题不需要它。Tashan 的第一步就是让投入与问题匹配，而不是对所有问题都展开长分析。

## 工作方式

1. **匹配投入**：能一两句定的事，就一两句答完并停，不展示过程；复杂问题才使用后续步骤。
2. **澄清**：区分期望结果与当前方案，先查已有证据，只问会改变决策的未决事实或取舍。
3. **第一性原理**：区分事实与假设，找出结果的真正成因，必要时重排步骤或拆开耦合环节；用户没给的数量是未知而非已知——要么标成假设并说明若不成立则换哪条路，要么删掉；把问题压缩成一句话——要决定什么、什么让它难。
4. **类比与重组**：把这句话还原为某个经典问题的变体，但先检验映射是否成立——说不出"什么导致什么、经典方法前提还成立哪些"就不写类比、整段跳过；成立则借其成熟方法，再放下类比，用第一性原理按当前约束重新组合。
5. **验证**：用证据或反例检验结论；把无法验证的前提写成条件，说明什么情况下方案不可行；错误代价高的决定，额外给一个能推翻结论的测试和一个提前停手的观察点。
6. **清晰作答**：先给结论，再给关键原因、行动建议和验证方式。

## 安装

把整个 `tashan/` 目录放入所用 Agent 的技能目录。以 CodeArts Agent 的项目级技能目录为例：

```
<project>/.codeartsdoer/skills/tashan/
```

其他 Agent 的目录约定不同，核心要求只有一条：`SKILL.md` 所在目录名为 `tashan`，且 frontmatter 中的 `name` 与目录名一致。

## 调用

`SKILL.md` 的 `description` 已声明适用场景，Agent 会在条件匹配时自动加载。也可以显式点名：

> 用 tashan 分析这个问题：……

## 示例

输入：

> 线上接口白天正常，高峰期响应从 200ms 涨到 4s，日志里没有明显报错。请定位原因。

使用 Tashan 后，典型输出会先给出结论和判断依据，再列出需要业务确认的取舍，最后给出可执行的改动与验证方式；而不是直接猜测某个中间件出了问题。

## 状态

这是一个精简版（40 行、约 4,200 字符），已通过 Agent Skills 格式校验。

2026-11-21 跑过一次小样本 pilot（8 题 × 2 臂、两个顺序对调的盲裁判，过程与原始数据见 [evals/pilot/iteration-1/benchmark.md](evals/pilot/iteration-1/benchmark.md)）：有 skill 的答案在 13 个有效判定中赢 11 个，五维总分 14.38 vs 13.69（满分 15），输出长度 1.05×。样本小、裁判同族、没有「等长通用提示」对照组，所以这只是方向信号，不足以宣称通用提升；简单题上它仍可能过度展开。

随后按这两个失败模式打了三处补丁（答完即停、未给的数量是未知、高价决定要有一条能证伪的测试），复测 3 题 × 2 臂：6 个判定全部判给新版本，13.33 vs 11.50，且不再出现虚构「吞吐没掉」或 simple 题长篇。过程见 [evals/pilot/iteration-2/RESULT.md](evals/pilot/iteration-2/RESULT.md)。

接着用一份等长的通用思考提示做对照（iteration-3，4 题，对照提示 3,678 字符 vs SKILL.md 4,193 字符）：skill 6:2 略胜，五维 14.25 vs 13.38，但两道量化分析题裁判各判一边。也就是说，相对「无提示」的优势里有一部分只是「被要求认真思考」带来的；目前稳定的差异集中在诊断题的未知量标注与可证伪测试、以及简单题上不展开。见 [evals/pilot/iteration-3/RESULT.md](evals/pilot/iteration-3/RESULT.md)。

又做了一次消融（iteration-4）：删掉第 4 步「经典问题 + 重组」后，4 题以 2:6 落后（13.25 vs 14.13），贡献集中在有真正同构经典问题的诊断/容量类题；但在纯算账题上这一步会多套一层框架、反而丢分。见 [evals/pilot/iteration-4/RESULT.md](evals/pilot/iteration-4/RESULT.md)。这仍不是通用提升的证据。

据此把第 4 步的退出条件写硬——先检验映射，说不出「什么导致什么、哪些前提还成立」就整段跳过、不谈类比——并在 h4（上一轮丢分题）与 h1（防止回退）上复测：新版 3 胜 1 平，14.75 vs 14.00，h4 不再硬套框架、h1 的排队机制与可证伪测试保留。见 [evals/pilot/iteration-5/RESULT.md](evals/pilot/iteration-5/RESULT.md)。

iteration-6 换了考题：不再测「会不会分析」，而是测核心能力之一「拷问」——三题两轮对话，看它在给出方案前是否问出会改变结论的未知、并在拿到回答后改建议；对照组是一份等长、同样要求先确认未知的通用思考提示。结果 1 胜 2 负 3 平，六维均分 17.50 vs 17.67。**但这份对照是在知道 skill 哪些点有效之后反向写的，内容与 skill 高度重合**，所以它测的是包装而不是内容：同样包含未知量、可证伪、答完即停时，六步排版与散文排版没有可测差异（with_skill 在 q1 还长了 1.75 倍却没赢）。它不能说明这些内容无效。见 [evals/pilot/iteration-6/RESULT.md](evals/pilot/iteration-6/RESULT.md)。

iteration-7 补上真正的对照：同样 3 题两轮，with_skill 对**无提示基线**（只给题面，不要求任何思考方式）。结果 6 个判定全部判给 skill，六维 17.50 vs 16.50，五维 14.67 vs 14.00；差距集中在两点——第一轮就把会改变结论的未知摆到方案前面，以及内部算术/口径少自相矛盾。基线本身并不弱（会质疑前提、会给公式），所以这不是「skill 会分析、基线不会」，而是「skill 先问再答、且更少前后矛盾」。注意 rubric 是按 skill 的原则写的，这个 6:0 是有偏的上界。见 [evals/pilot/iteration-7/RESULT.md](evals/pilot/iteration-7/RESULT.md)。

iteration-8 换到豆包、换四道题（支付回调尾延迟、六个月微服务化、客服首响 30 分钟、数据库账单三倍），A 臂给技能正文、B 臂只给题面，两个盲裁判的甲乙映射相反。结果 8 个判定全给 A，五维 14.875 vs 11.875，裁判一致 4/4，长度 1.25×。差距集中在验证/判据与未知量：A 给阈值、反证分支和停手线；B 的诊断同样准确（线程栈、拆账单、驳斥排名），但收尾停在「基本能定案」。同族裁判 + 按 skill 原则写的 rubric，这个分差仍是上界；它支持「收尾更完整」，不支持「分析更强」。见 [evals/pilot/iteration-8/RESULT.md](evals/pilot/iteration-8/RESULT.md)。
